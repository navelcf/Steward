**`compose`**
**子命令：用 `docker-compose.yml` 来管理容器。**
**因为你的 PG 是 compose 起的，不是 `docker run` 手动起的，所以要用这个子命令。**


**`exec`**
**子命令：在「已经在运行的容器」里执行一条命令。**


**`-T`**
**选项：不分配伪终端（TTY）**


**`postgres`**
**这是 compose 文件里的「服务名」。**
**看你 `docker-compose.yml`**

services:
  postgres:        ← 这个名字
    image: postgres:18


**`psql -U steward -d steward -c "SELECT 1;"`**

**从这里开始，全部是「要在容器内部执行的命令」，和 docker 没关系了。**
**`psql` 是 PG 自带的命令行客户端，容器里已经装好了。** 所以可以直接用。
它自己的三个参数：
参数	全名	意思
-U steward	--user	用 steward 这个数据库用户连
-d steward	--dbname	连 steward 这个库
-c "SELECT 1;"	--command	执行这条 SQL，执行完就退出，`-c` 是「执行一条 SQL 然后走人」，适合脚本。

也是直接免密：
docker compose exec -T postgres psql -U steward -d steward -h 127.0.0.1 -c "SELECT 1;"

真正要密码：
compose 端口映射是 `127.0.0.1:5432:5432`
连接从 Windows 出发，经过 Docker Desktop 的端口转发进入容器。到达容器时，来源 IP 不是 `127.0.0.1`，而是 Docker 的网关地址（类似 `172.x.x.1`）

取回代码：
只想看看 —— `git show`（零风险）
git show 0762491:src/steward/main.py


把某个文件恢复成某次提交的样子：
git restore --source=0762491 src/steward/main.py
保险做法：先 stash 或先 commit。
git stash                                    # 先存起来
git restore --source=0762491 src/steward/main.py
git stash pop                                # 想找回来就 pop


整个项目临时「穿越」到某次提交（看完就回来）：
git switch --detach 0762491
效果：整个代码树变成那次的样，进入「游离 HEAD」状态。
看完回来：
git switch main


退回某个提交，但历史保留（最安全）：
git revert 93a4b40
**效果：生成一个**新提交**，内容是「把 93a4b40 的改动反向撤销」。**
**原始的两个提交还在历史里，只是多了一条「撤销记录」。**
**适合：已经 push 过、或者多人协作的仓库。**
**代价：会多两条 commit（原提交 + 撤销提交）。**


硬退回某个提交（历史被改写）：
git reset --hard 0762491
效果：`main` 直接指到 `0762491`，后面两个提交从这个分支上消失。
用 `reset --hard` 也不怕 —— `git reflog` 是后悔药：
git reflog
# 找到 9669486 那行，然后
git reset --hard 9669486
reflog 默认保留 90 天。
