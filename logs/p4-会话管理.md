之前测试数据库的时候发现：

users 表的id是自动递增的，但是之前测试的时候，加入了1，2，3，然后全部删掉，那么存进去就是4，

这是个小问题，理论上没有丝毫影响！

`BIGSERIAL` 背后是一个\*\*独立的序列对象 `users\_id\_seq`。它唯一的工作就是 “发号”。

`DELETE` 只删表里的行，\*\*完全不碰\*\*这个序列。所以号照旧往前发。




\-- 办法一：清空整表并把序列归零（会删掉 cs@example.com）

TRUNCATE users RESTART IDENTITY;



\-- 办法二：只重置序列（但下次插入会和已有 id 冲突）

ALTER SEQUENCE users\_id\_seq RESTART WITH 1;



无论哪种都不好，特别是以后，如果要删除某个用户，使用方法二，那绝对会出问题，我认为现在能跑就行，不管了



特别提醒，又忘记了：

方法	语义	幂等

GET	读	是

POST	新建一个	否

PUT	整体替换	是

PATCH	局部修改	不一定

DELETE	删掉	是
