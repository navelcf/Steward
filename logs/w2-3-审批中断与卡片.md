日志等级从高到低：

debug < info < warning < error < critical

`exception` \*\*不是等级\*\*，它是 `error` 的快捷写法：等价于 `error(..., exc\\\_info=True)`，会自动把\*\*当前异常的完整 traceback\*\*带出来。



&#x09;用在哪	打出来是什么

logger.info	正常流程走完了	一行彩色文本 + 你的 key=value

logger.warning	不太对但能继续	同上，黄色

logger.error	出错了，不带 traceback	红色

logger.exception	出错了，要 traceback，且必须在 except 里	红色 + 完整调用栈



关于幂等性：

词	说的是什么	你项目里谁

幂等	做 1 次和 N 次，结果一样	adelete\_thread、create\_from\_interrupt

防重	第二次直接拒绝	decide（409）

原子	要么全做、要么全不做	alarm 那个事务：删表 + 删 checkpoint 要么一起成、要么都不成（你现在是「分两段」，所以不完全原子，靠日志兜）



现在 `delete\\\_thread` 的写法：业务表 commit → checkpoint 事务外删。这不是原子的（中间崩了会留孤儿 checkpoint），但\*\*是幂等的\*\*（重试一次就能把孤儿清掉）。这个取舍是对的 —— 因为 checkpoint 那步失败不抛，用户可以放心重试。



\# 英文词源（顺手记一下）

`idempotent` = `idem`（拉丁语「同一个」）+ `potens`（「力量」）。

合起来：\*\*「同样的力量」\*\*—— 你做多少次，力量都一样，不会因为你多做几次就变大。

数学上写成 `f(f(x)) = f(x)`。跟你项目里的 `adelete\\\_thread` 完全对得上：删一次得到空表，再删还是空表。
