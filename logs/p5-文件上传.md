客户端 multipart/form-data

UploadFile.filename 是客户端传的，可以随便写。如果直接拼：



storage/{user\_id}/ + "../../.env"

就能写到项目外甚至覆盖配置文件。这叫路径穿越



哦，牛逼，还有这种东西？这么厉害？



两层防御：

根本不用原始文件名存盘：只用 Path(filename).suffix 取出后缀，文件名整体换成 str(uuid4())。攻击者写什么都影响不了落盘路径。

仍然做 resolve() + is\_relative\_to() 校验：这是防御性编程 —— 今天路径里全是自己生成的 uuid 和 int，理论上跑不出去；但哪天有人改成「保留原始文件名以便下载」，这层校验就是唯一的刹车。两层都在，才叫安全。

`uuid4()` 的用途是 “造一个标识，这辈子造出来的任意两个都不用担心撞”。它的目标是 “唯一”，随机只是为了达成唯一。





为什么文件出参不提供path：

\# 为什么故意没有 `path`

> 

> \*\*绝不把服务端绝对路径返回给客户端，那会泄露目录结构，也给攻击者提供信息。\*\*



\*\*如果返回了 `E:\\Steward\\storage\\4\\6b1....docx`：\*\*



\- \*\*攻击者知道了你的按 `user\_id` 分目录\*\*

\- \*\*知道了你的 `storage` 在哪个根\*\*

\- \*\*知道了 ID 格式，可以拿来试探别人的\*\*



\*\*客户端只需要 `file\_id`，凭它加上自己的 token，就能让服务端把文件找出来。路径是服务端内部的事。\*\*







\### `open("xb")` 里的 `x`

\*\*`open` 的 mode 有四个开关字母：\*\*

字母	含义

w	写，已存在就清空覆盖

a	追加，已存在就往后写

x	独占创建，已存在就报错

r	读



`xb` = 独占创建 + 二进制模式。



状态码：

首位	含义	记忆

2xx	成功	一切正常

3xx	重定向	去别处拿

4xx	你（客户端）的问题	请求本身有问题，改请求

5xx	我（服务端）的问题	请求没问题，是我坏了





码	名字	什么时候用	你项目里出现在哪

200	OK	查到了、改成功了	GET / PATCH

201	Created	新建了一个东西	POST /register、POST /threads、POST /files

204	No Content	删成功了，没内容可返回	DELETE /threads

400	Bad Request	请求本身有问题	UnsupportedFileError（后缀不支持）

401	Unauthorized	我不知道你是谁	get\_current\_user（没 token /token 无效）

403	Forbidden	我知道你是谁，但你不许干	你故意不用，见下一节

404	Not Found	东西不存在，或者不是你的	ThreadNotFoundError

409	Conflict	状态冲突（比如审批已处理过）	P1 的审批模块

413	Content Too Large	请求体太大	FileTooLargeError

422	Unprocessable Entity	格式是对的，但字段校验没过	FastAPI 自动抛，你不用写

500	Internal Server Error	服务端自己挂了	任何没被接住的异常
