## 2.5 PowerShell 使用须知（这一节专门为 Windows 写的，别跳过）

手册和很多教程里的命令是 Linux/macOS 的 bash。你用 PowerShell，直接照抄会踩坑。先花 5 分钟看完这一节。

### 2.5.1 先确认你的 PowerShell 版本

```powershell
$PSVersionTable.PSVersion
```

预期类似：

```text
Major  Minor  Build  Revision
-----  -----  -----  --------
5      1      26100  0
```

- **5.1**（Windows 自带的 `powershell.exe`）：下面 2.5.3 的 BOM 坑一定会遇到
- **7.x**（`pwsh`）：BOM 坑不存在，但按本教程的写法也照样能跑

### 2.5.2 命令对照表（bash → PowerShell）

| 别处看到的 bash | PowerShell 里用 | 说明 |
| --- | --- | --- |
| `cd /e/Steward` | `Set-Location E:\Steward` | 路径用反斜杠；`cd` 是别名，也能用 |
| `pwd` | `Get-Location` | 输出是个表格，看 `Path` 列 |
| `cat 文件` | `Get-Content 文件` | `cat` 在 PowerShell 里也是 `Get-Content` 的别名，能用，但写全名更清楚 |
| `tail -n 6 文件` | `Get-Content 文件 -Tail 6` | 看文件末尾几行 |
| `ls -la` | `Get-ChildItem -Force` | `-Force` 才显示隐藏文件 |
| `cp a b` | `Copy-Item a b` | |
| `mkdir -p a b` | `New-Item -ItemType Directory -Force -Path a,b` | `-Force` 会连中间目录一起建 |
| `touch f` | `New-Item -ItemType File -Force -Path f` | |
| `grep -m 3 x 文件` | `Select-String -Path 文件 -Pattern x \| Select-Object -First 3` | |
| `grep -A 10 x 文件` | `Select-String -Path 文件 -Pattern x -Context 0,10` | 显示匹配行 + 后 10 行 |
| `find src -type f \| sort` | `Get-ChildItem -Path src -Recurse -File \| Select-Object -ExpandProperty FullName \| Sort-Object` | |
| `cat > 文件 <<'EOF'` | 见 2.5.3 | PowerShell 没有 bash heredoc |
| `netstat -ano \| findstr 5432` | `netstat -ano \| Select-String ":5432"` | `findstr` 是外部命令，也能用 |
| **`curl -i 网址`** | **`curl.exe -i 网址`** | ⚠️ 见 2.5.4，最容易踩 |

### 2.5.3 坑一：写文件时的 UTF-8 BOM（Windows PowerShell 5.1 特有）

PowerShell 5.1 里 `Set-Content -Encoding utf8` 会在文件开头写入 3 个字节 `EF BB BF`（BOM）。后果：

- `.env` 带 BOM → 第一个键变成 `\ufeffAPP_NAME`，`pydantic-settings` 读不到它，配置会悄悄回退默认值
- `pyproject.toml` 带 BOM → `TOMLDecodeError`，`uv add` 直接失败
- `.gitignore` 带 BOM → 第一行规则失效，`.env` 可能被提交上去

**本教程的做法**：所有「新建 / 修改文件」的步骤，**推荐用编辑器**（VS Code / 记事本）把内容粘进去，另存为 **UTF-8 无 BOM**；命令只用来查看、执行、验证。这样最直观，也避开 here-string 的各种坑。

如果你确实想全程用 PowerShell 写文件，用这个**无 BOM 写法**（下面以 `.gitignore` 为例，把中间换成你要的内容）：

```powershell
$text = @'
# ---- Python 生成物 ----
__pycache__/
'@

[System.IO.File]::WriteAllText(
    "$PWD\.gitignore",
    $text,
    [System.Text.UTF8Encoding]::new($false)
)
```

三条规矩：

1. `@'` 单独一行开头，`'@` 单独一行结尾，**`'@` 必须顶格写在第 0 列**，前面不能有空格，否则语法错误
2. `@'...'@` 是**单引号 here-string**，里面的 `$` 不会被 PowerShell 展开；用 `@"..."@` 会展开，写配置文件时不要用
3. `[System.Text.UTF8Encoding]::new($false)` 的 `$false` 就是「不要 BOM」，别漏

**怎么检查文件有没有 BOM**：

```powershell
$b = [System.IO.File]::ReadAllBytes("$PWD\.env")
'{0:X2} {1:X2} {2:X2}' -f $b[0], $b[1], $b[2]
```

- 输出 `EF BB BF` → 有 BOM，用编辑器「另存为 UTF-8 无 BOM」，或重新用上面的 `WriteAllText` 写一遍
- 输出类似 `41 50 50`（`APP` 的 ASCII）→ 正常

> PowerShell 7 的 `-Encoding utf8` 默认无 BOM，所以 `Set-Content -Encoding utf8` 在 7 里是安全的。但写成上面那种写法，5.1 / 7 通吃。

### 2.5.4 坑二：`curl` 不是 curl

**Windows PowerShell 5.1 里 `curl` 是 `Invoke-WebRequest` 的别名**，所以 `curl -i http://...` 会报「找不到与参数名称 i 匹配的参数」这类错误。必须写：

```powershell
curl.exe -i http://127.0.0.1:8001/health
```

加 `.exe` 就会调用真正的 curl（Windows 10/11 自带 `C:\Windows\System32\curl.exe`）。PowerShell 7 已经移除了这个别名，但写 `curl.exe` 在两个版本里都稳。

> 如果你更想用 PowerShell 原生方式：`Invoke-WebRequest -Uri http://127.0.0.1:8001/health` 也能拿到结果，但输出格式和 curl 不同，教程里统一用 `curl.exe`，方便和手册对照。

### 2.5.5 坑三：单引号 / 双引号 / 方括号

| 场景 | 写法 | 原因 |
| --- | --- | --- |
| 传给 `python -c` 的代码 | `uv run python -c "import steward; print(steward.__file__)"` | 外层双引号，Python 代码里的字符串用单引号；整条命令里不要出现 `$` |
| 环境变量（临时） | `$env:UV_DEFAULT_INDEX = "https://..."` | 用 `$env:` 前缀；用完 `Remove-Item Env:UV_DEFAULT_INDEX` |
| 带 extras 的包名 | `uv add "uvicorn[standard]"` | PowerShell 里方括号**不是**通配符，但加引号仍推荐：和文档写法一致，也避免别的 shell 里出问题 |
| 路径 | `'src/steward/core'` 或 `"E:\Steward"` | 正斜杠反斜杠 PowerShell 都认 |

### 第二步：逐行解释（这文件以后你会天天改，值得花 3 分钟）

| 行 | 意思 |
| --- | --- |
| `[project]` | PEP 621 规定的标准项目元数据表，所有 Python 打包工具都认 |
| `name = "steward"` | 包名。src 布局下 uv 会去找 `src/steward/`，`import steward` 才能成功 |
| `version = "0.1.0"` | 版本号，P0 阶段不用改 |
| `description` | 一行简介。模板是占位文字，换成项目名即可 |
| `readme = "README.md"` | 指向 README；文件现在是空的，Day 7 写 |
| `authors` | 作者信息，uv 从你 git 配置里带出来的 |
| `requires-python = ">=3.12"` | 允许的解释器范围。uv 结合 `.python-version` 选了 3.12.8 |
| `dependencies = []` | **现在是空的**。A3 里我们不手写它，让 `uv add` 一条条往里填 |
| `[project.scripts]` | 定义命令行入口。装完会在 `.venv\Scripts\` 生成 `steward.exe` |
| `steward = "steward:main"` | 冒号前是模块（`steward` 包），冒号后是函数（`main`）。它指向 `src\steward\__init__.py` 里那个模板函数 `print("Hello from steward!")` |
| `[build-system]` | 告诉 uv 用哪个后端构建本项目 |
| `build-backend = "uv_build"` | `uv sync` 会把本项目以 **editable（可编辑）** 方式装进 venv，所以你在 `src\` 改代码不用重新装包。这是后面所有 `uv run` 能找到你的代码的原因 |

## A2. 配置清华源（这一节单独讲清楚）

v1 里我把这 3 行偷偷混进了一大段 TOML 里没解释，这里补全。

### A2.1 它是什么、为什么需要

`uv`（以及 pip）默认从 `https://pypi.org/simple` 下载包。这个站在国外，国内拉几十个包经常很慢甚至超时。清华源 `https://pypi.tuna.tsinghua.edu.cn/simple` 是 PyPI 的国内镜像，内容和官方同步，下载快很多。

你原来的 `D:\ai_xuexi\agent基础\pyproject.toml` 里就有这段，所以这是沿用你的习惯，不是新发明：

```toml
[[tool.uv.index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
```

### A2.2 三种配法对比，我们选哪种

| 做法 | 怎么写 | 优点 | 缺点 | 选不选 |
| --- | --- | --- | --- | --- |
| 每次命令行带环境变量 | `$env:UV_DEFAULT_INDEX = "https://pypi.tuna.tsinghua.edu.cn/simple"` | 不改任何文件 | 每开一个新窗口都要设一次；换台机器 / 别人 clone 下来不知道 | ❌ |
| 写进用户全局配置 `%APPDATA%\uv\uv.toml` | 全局 `[[index]]` | 所有项目都生效 | 只对你这台机器生效，项目不可复现；以后换源会连累别的项目 | ❌ |
| **写进项目的 `pyproject.toml`** | `[[tool.uv.index]]` + `default = true` | 跟着 Git 走，clone 下来就生效；每个项目可独立配 | 多 3 行配置 | ✅ **选这个** |

`[[tool.uv.index]]` 是**数组的表**（双方括号），意思是可以配多个镜像源；`default = true` 指定默认用哪一个，不写的话 uv 可能仍把 pypi.org 当首选。

> 临时设的环境变量用完记得清掉：`Remove-Item Env:UV_DEFAULT_INDEX`。

### A2.3 为什么必须在第一次 `uv add` **之前**做

`uv.lock` 会记录每个包是从哪个 registry 下载的。如果先 `uv add` 再改源，锁文件里已经写下了 pypi.org，改完还得 `uv lock --upgrade` 重新解析一遍。现在 `uv.lock` 还是 `uv init` 生成的 128 字节空文件，一个包都没锁，**这时候配最干净**。

### A2.4 动手：往文件末尾追加 3 行

**推荐做法（避开 BOM 坑）**：用编辑器打开 `pyproject.toml`，把下面这段粘到**文件最末尾**，保存为 UTF-8 无 BOM：

```toml

[[tool.uv.index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
```

> 开头的空行是故意留的，让新段落和 `[build-system]` 隔开；TOML 里空行不影响解析。

**PowerShell 备选**（无 BOM 追加写法，见 2.5.3）：

```powershell
$append = @'

[[tool.uv.index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
'@

$path = "$PWD\pyproject.toml"
$all  = [System.IO.File]::ReadAllText($path) + $append
[System.IO.File]::WriteAllText($path, $all, [System.Text.UTF8Encoding]::new($false))
```

> ⚠️ 不要用 `Add-Content -Encoding utf8`：在 PowerShell 5.1 里它可能往追加位置写 BOM 字节（见 2.5.3）。上面这种「读全文 + 拼接 + 一次性无 BOM 写回」最稳。
> 也不要写成 `>`（`>` 在 PowerShell 里是 `Out-File` 的重定向，会**覆盖**整个文件，把手滑变成灾难）。

核对末尾：

```powershell
Get-Content pyproject.toml -Tail 6
```

预期（可能从空行开始，看到这三行内容即可）：

```text
[build-system]
requires = ["uv_build>=0.13.0,<0.14.0"]
build-backend = "uv_build"

[[tool.uv.index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"

```

再确认 TOML 没被写坏、配置被读到了：

```powershell

```

预期：

```text
[{'url': 'https://pypi.tuna.tsinghua.edu.cn/simple', 'default': True}]
```

> 用 Python 标准库 `tomllib`（3.11+ 自带）解析文件，比肉眼可靠。报 `TOMLDecodeError` 就回去对照 `Get-Content -Tail` 的输出，检查有没有多了字符或用了中文引号。

### A2.5 怎么验证真的生效

**现在还没装任何包，`uv.lock` 里没有 registry 记录**，所以这一刻只能验证配置被读到了（上面那条 `tomllib` 命令）。等 A3 第一条 `uv add` 跑完，再验证：


预期看到：

```text

```

（前面的 `uv.lock:NN:` 是 `Select-String` 加的文件名和行号，正常。）

如果看到 `https://pypi.org/simple`，说明源没生效：回 A2.4 确认那 3 行写进了**项目根**的 `pyproject.toml`，然后跑 `uv lock --upgrade` 重新解析。

### A2.6 这一节的常见坑

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| 用 `>` 把文件冲掉了 | 手滑，PowerShell 里 `>` 是覆盖重定向 | 按 A1.5 的模板恢复，再重做 A1/A2 |
| `TOMLDecodeError` | 粘贴时多了字符 / 用了中文引号 / 文件带 BOM | `Get-Content -Tail 6` 对照；按 2.5.3 检查 BOM |
| 配了还是慢 | 没写 `default = true`，或 `uv.lock` 里还是旧 source | 确认配置；`uv lock --upgrade` |
| `Set-Content -Encoding utf8` 之后 uv 报错 | 5.1 的 BOM | 用 2.5.3 的 `WriteAllText` 无 BOM 写法重写 |
| 别人 clone 后走的不是清华源 | 他把 `pyproject.toml` 改了 | 这段配置本身跟着 Git 走，不用额外操作 |
| 想临时换回官方源 | — | `$env:UV_DEFAULT_INDEX = "https://pypi.org/simple"` 后 `uv add xxx`，用完 `Remove-Item Env:UV_DEFAULT_INDEX` |

## A3. 今天要用的依赖，一条条 `uv add`

### A3.1 先搞懂 `uv add` / `uv sync` / `uv run` 三者关系

| 命令 | 干了什么 | 什么时候用 |
| --- | --- | --- |
| `uv add <包名>` | ① 解析版本 ② **把包名+版本下界写进 `pyproject.toml` 的 `dependencies`** ③ 更新 `uv.lock` ④ 装进 `.venv` | 你要引入一个新库的时候 |
| `uv sync` | 按 `uv.lock` 把 `.venv` 补齐/对齐（不修改 `pyproject.toml`） | clone 下来第一次、或手动改了 lock 之后 |
| `uv run <命令>` | 在 `.venv` 环境里执行；若环境落后于 lock，会先自动 sync | 跑服务、跑测试、跑脚本 |

所以 **`uv add` 已经包含了安装**，A3 跑完不需要再 `uv sync` 一遍（跑了也无害，只是空转）。

`uv add --dev <包名>` 会把包写进 `[dependency-groups] dev`，表示「只有开发时需要，部署时不用」。uv 默认会安装 dev 组，生产环境用 `uv sync --no-dev` 排除。

### A3.2 为什么不一上来把 11 个依赖全装了

v1 那么写，问题有三个：

1. **不知道谁用**：装了 `pwdlib`、`pyjwt`、`python-docx`，但今天的代码一行都没 import 它们。过两天你会分不清「哪些是必须的、哪些是当时顺手装的」。
2. **排查变难**：装得越多，依赖冲突、下载失败的概率越大；出问题时不知道是哪个包带进来的。
3. **和手册节奏脱节**：手册每天有明确目标，依赖也该跟着每天的目标走。

**用到才加**的好处是：每敲一次 `uv add`，你都清楚「因为今天要写 `config.py`，所以需要 `pydantic-settings`」。这个因果关系本身就是学习。

## A5. 追加 `[tool.ruff]` 配置（还是追加，不重写）

现在 `ruff` 装好了，但没配置的话它用默认规则（行宽 88、规则集只有 E4/E7/E9/F）。我们要让它按项目规范检查。

**推荐做法**：编辑器打开 `pyproject.toml`，把下面这段粘到**文件最末尾**，保存为 UTF-8 无 BOM：

```toml

[tool.ruff]
line-length = 100
target-version = "py312"
src = ["src"]

[tool.ruff.lint]
select = ["E", "F", "I"]
```

**PowerShell 备选**（无 BOM 追加，同 A2.4）：

```powershell
$append = @'

[tool.ruff]
line-length = 100
target-version = "py312"
src = ["src"]

[tool.ruff.lint]
select = ["E", "F", "I"]
'@

$path = "$PWD\pyproject.toml"
$all  = [System.IO.File]::ReadAllText($path) + $append
[System.IO.File]::WriteAllText($path, $all, [System.Text.UTF8Encoding]::new($false))
```

逐行解释：

| 行 | 为什么 |
| --- | --- |
| `line-length = 100` | 88 太窄，类型标注一长就换行；100 是常见折中 |
| `target-version = "py312"` | 告诉 ruff 按 3.12 语法检查，才不会把 `str \| None` 这种写法误判 |
| `src = ["src"]` | **src 布局必填**：ruff 靠它知道 `steward.*` 是本项目的一级包，import 排序时才不会把它当第三方库塞到中间 |
| `select = ["E","F","I"]` | E=风格错误、F=致命错误（未定义变量、无用 import）、I=import 排序。第一周只开这三类，不做过度检查；`B`/`UP` 等以后再加 |

核对：

```powershell
Get-Content pyproject.toml -Tail 10
uv run python -c "import tomllib,pathlib; d=tomllib.loads(pathlib.Path('pyproject.toml').read_text(encoding='utf-8')); print(d['tool']['ruff']['lint'])"
```

## A9. `src\steward\core\config.py`

**这个文件是干什么的**：整个项目唯一的「配置入口」。以后任何地方要读端口、数据库地址、密钥，都写 `from steward.core.config import settings`，不再各自 `os.getenv(...)`。这样改配置只改一处，也不会有人把密钥硬编码在业务代码里。

**用编辑器新建这个文件**，粘贴：

```python
from __future__ import annotations

from pathlib import Path

from pydantic import Field, computed_field
from pydantic_settings import BaseSettings, SettingsConfigDict
from sqlalchemy.engine import URL

# src/steward/core/config.py 往上数 3 层才是项目根 E:\Steward：
# core -> steward -> src -> 项目根。手册里的平铺布局只需要 parents[2]。
APP_ROOT = Path(__file__).resolve().parents[3]


class EnvSettings(BaseSettings):
    """所有配置分组的公共基类：统一从项目根 .env 读取。"""

    model_config = SettingsConfigDict(
        env_file=(APP_ROOT / ".env",),
        env_file_encoding="utf-8",
        extra="ignore",
        case_sensitive=False,
    )


class AppSettings(EnvSettings):
    name: str = Field(alias="APP_NAME", default="Steward")
    host: str = Field(alias="APP_HOST", default="127.0.0.1")
    port: int = Field(alias="APP_PORT", default=8001)
    debug: bool = Field(alias="APP_DEBUG", default=True)


class DatabaseSettings(EnvSettings):
    host: str = Field(alias="DB_HOST", default="127.0.0.1")
    port: int = Field(alias="DB_PORT", default=5432)
    name: str = Field(alias="DB_NAME", default="steward")
    user: str = Field(alias="DB_USER", default="steward")
    password: str = Field(alias="DB_PASSWORD", default="")
    echo: bool = Field(alias="DB_ECHO", default=False)
    pool_size: int = Field(alias="DB_POOL_SIZE", default=5)
    max_overflow: int = Field(alias="DB_MAX_OVERFLOW", default=10)
    pool_recycle: int = Field(alias="DB_POOL_RECYCLE", default=1800)

    @computed_field
    @property
    def url(self) -> str:
        """交给 SQLAlchemy 的 asyncpg 连接串。

        用 URL.create 而不是手拼字符串：密码里的 @ : / 会被自动转义，
        手册附录 B 的 InvalidPasswordError 从根上就不会发生。
        """
        return URL.create(
            drivername="postgresql+asyncpg",
            username=self.user,
            password=self.password,
            host=self.host,
            port=self.port,
            database=self.name,
        ).render_as_string(hide_password=False)


class AuthSettings(EnvSettings):
    # 故意不设默认值：忘了配就直接启动失败，比悄悄用弱密钥安全
    secret: str = Field(alias="JWT_SECRET", min_length=32)
    expire_minutes: int = Field(alias="JWT_EXPIRE_MINUTES", default=120)


class LoggingSettings(EnvSettings):
    level: str = Field(alias="LOGGING_LEVEL", default="INFO")


class Settings(BaseSettings):
    app: AppSettings = Field(default_factory=AppSettings)
    db: DatabaseSettings = Field(default_factory=DatabaseSettings)
    auth: AuthSettings = Field(default_factory=AuthSettings)
    logging: LoggingSettings = Field(default_factory=LoggingSettings)


settings = Settings()
```

### 逐段讲原理

1. **`from __future__ import annotations`**（方案 12.2 第 6 条）：让类型标注延迟求值，写 `str | None`、`list[dict]` 不用怕循环引用。以后每个 `.py` 都放这一行。
2. **`APP_ROOT = ...parents[3]`**：见第 2 节路径对照表，src 布局特有。写错 → 找不到 `.env` → 所有配置回退默认值 → `JWT_SECRET` 报必填。这是今天第二容易踩的坑。
3. **`EnvSettings` 公共基类**：`env_file` 统一指向项目根 `.env`；`extra="ignore"` 表示 `.env` 里多出来的键不会让配置类报错；`case_sensitive=False` 让环境变量名大小写不敏感。
4. **`Field(alias="DB_HOST")`**：alias 就是环境变量名。pydantic-settings 用它去 `.env` / 系统环境变量里取值。
5. **按域分组**（方案 12.4）：`app` / `db` / `auth` / `logging` 各自一类，`settings.db.port` 一眼知道属于哪块，不会攒成几十个字段的大类。
6. **`Settings` 用 `default_factory` 组装**：实例化 `Settings()` 时，四个子类各自去读 `.env` 里自己那几个键。
7. **`settings = Settings()` 放模块级是安全的**：它只读文本配置，**不建任何连接**。方案 12.2 第 3 条禁止的是「模块级创建连接/客户端」，别把两件事混了。真正的数据库引擎 Day 2 会放进 `lifespan`。
8. **`URL.create` 拼连接串**：手册用 pydantic 的 `PostgresDsn.build`，但 `postgresql+asyncpg` 这个 scheme 在不同 pydantic 版本里表现不一致；SQLAlchemy 自己的 `URL.create` 专干这个，自动转义密码里的 `@ : /`。**这是我有意偏离手册的一处**，原因是可靠性。今天装 `sqlalchemy[asyncio]` 就是为了这行 import。
9. **`computed_field` + `@property`**：让 `url` 像普通属性一样读（`settings.db.url`），但每次重新计算；顺序是 `computed_field` 在外、`property` 在内，别写反。
10. **`secret` 不给默认值 + `min_length=32`**：忘配置就启动失败，属于「快速失败」。如果给默认值，开发时一切正常，上线后所有 JWT 都能被伪造，而且不会报错——正是方案第 18 章说的「静默错误」。

## A10. `src\steward\core\logging.py`

**这个文件是干什么的**：把标准库 `logging` 和 `structlog` 接起来，让全项目用一种方式打日志。业务代码里一律 `get_logger(__name__)`，不许 `print`。

**用编辑器新建**，粘贴：

```python
from __future__ import annotations

import logging
import sys

import structlog


def configure_logging(level: str = "INFO") -> None:
    """把标准库 logging 与 structlog 接起来，控制台彩色、生产可换 JSON。"""
    log_level = getattr(logging, level.strip().upper(), logging.INFO)

    root = logging.getLogger()
    root.setLevel(log_level)
    root.handlers.clear()

    handler = logging.StreamHandler(sys.stdout)
    handler.setLevel(log_level)
    handler.setFormatter(logging.Formatter("%(message)s"))
    root.addHandler(handler)

    structlog.configure(
        processors=[
            structlog.contextvars.merge_contextvars,
            structlog.stdlib.add_logger_name,
            structlog.stdlib.add_log_level,
            structlog.processors.TimeStamper(fmt="%Y-%m-%d %H:%M:%S", utc=False),
            structlog.processors.StackInfoRenderer(),
            structlog.processors.format_exc_info,
            structlog.dev.ConsoleRenderer(colors=True),
        ],
        wrapper_class=structlog.stdlib.BoundLogger,
        logger_factory=structlog.stdlib.LoggerFactory(),
        cache_logger_on_first_use=True,
    )

    # SQLAlchemy 会把每条 SQL 都打出来，太吵；单独压到 WARNING
    logging.getLogger("sqlalchemy.engine").setLevel(logging.WARNING)


def get_logger(name: str) -> structlog.stdlib.BoundLogger:
    """按模块名取 logger，业务代码里一律用它，不用 print。"""
    return structlog.get_logger(name)
```

逐段解释：

| 片段 | 为什么 |
| --- | --- |
| `root.handlers.clear()` | uvicorn 自己也会装 handler，不清会出现每行日志打两遍 |
| `StreamHandler(sys.stdout)` + `Formatter("%(message)s")` | 具体渲染交给 structlog，标准库这层只负责把消息送到 stdout，不再套一层时间/级别前缀 |
| `merge_contextvars` | 方案 12.5 要求日志带 `request_id`/`user_id`/`thread_id`/`run_id`；Day 7 加中间件时把这些放进 contextvars，这里自动附加，业务代码一行不用改 |
| `TimeStamper(...utc=False)` | 本地时间，看日志不用心算 +8 |
| `ConsoleRenderer(colors=True)` | 开发时彩色好读；生产换 `JSONRenderer` 即可，业务代码不用动 |
| `logging.getLogger("sqlalchemy.engine").setLevel(WARNING)` | Day 2 起 SQLAlchemy 会把每条 SQL 打出来，太吵 |
| `-> structlog.stdlib.BoundLogger` | 返回类型写清楚，IDE 才能补全 `.info()` / `.error()` |

### 为什么不用 `print`

- `print` 没有级别、没有模块名、没法带结构化字段，也没法被日志系统收集。
- 方案 12.2 第 4 条：**禁止 print，统一 `get_logger(__name__)`**。
- 结构化写法是 `logger.info("应用启动", app=settings.app.name, port=settings.app.port)`，把字段**当参数传**；写成 f-string 就把变量拼进文本了，日志系统没法按 `port` 过滤、没法统计。这也是我不照抄手册 `main.py` 示例的地方。

## A11. `src\steward\main.py`

**这个文件是干什么的**：应用入口。只负责「组装」——建 `FastAPI` 实例、挂生命周期、注册路由。业务和 SQL 一律放 `modules\`（方案 3.2 强制分层）。

**用编辑器新建**，粘贴：

```python
from __future__ import annotations

from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

import uvicorn
from fastapi import FastAPI

from steward.core.config import settings
from steward.core.logging import configure_logging, get_logger

configure_logging(settings.logging.level)
logger = get_logger(__name__)


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    """应用生命周期：外部资源只在这里创建和释放。

    方案 12.2 第 3 条：禁止模块级创建连接/客户端。
    Day 2 会在这里加 check_database() / close_database()。
    """
    logger.info("应用启动", app=settings.app.name, port=settings.app.port)
    yield
    logger.info("应用关闭", app=settings.app.name)


app = FastAPI(
    title=settings.app.name,
    version="0.1.0",
    debug=settings.app.debug,
    lifespan=lifespan,
)


@app.get("/health", summary="健康检查", tags=["ops"])
async def health() -> dict[str, str]:
    """给探活和 Day 2 的健康检查用；今天只返回静态 ok。"""
    return {"status": "ok"}


if __name__ == "__main__":
    uvicorn.run(
        "steward.main:app",
        host=settings.app.host,
        port=settings.app.port,
        reload=True,
    )
```

逐段解释：

1. **import 顺序**：标准库 → 第三方 → 本项目。A5 配的 `I` 规则会检查这个，写反了 `ruff check` 会报 `I001`。
2. **`configure_logging(...)` 放模块级**：这是配置日志，不是建连接，规范允许（手册也这么做）。必须在创建 `logger` 之前调用。
3. **`@asynccontextmanager` + `yield`**：`yield` 之前是启动阶段，之后是关闭阶段。今天里面只有日志，**位置先留好**，Day 2 挂数据库、Day 6 挂模型客户端时不用改结构。
4. **`AsyncIterator[None]` 返回类型**：`asynccontextmanager` 要求生成器是异步的，标注写清楚，mypy 以后才查得动。
5. **`lifespan=lifespan`**：告诉 FastAPI 用哪个生命周期管理器。漏了这行，`lifespan` 函数永远不会执行。
6. **`@app.get("/health", ..., tags=["ops"])`**：`summary` 和 `tags` 会出现在 `/docs` 页面上，属于接口文档的一部分。
7. **`if __name__ == "__main__"`**：允许 `python -m steward.main` 启动；平时用 `uvicorn` 命令，这段是备用入口。
8. **启动模块名是 `steward.main:app`，不是 `app.main:app`**：手册是平铺布局，你是 src 布局。写错会 `ModuleNotFoundError: No module named 'app'`——今天最容易踩的坑。

> 方案 5.1 要求所有响应带 `X-Request-Id`，今天**先不加**。Day 7 收尾时统一加一个中间件，一次讲清楚 `contextvars`，比今天夹带一个半懂的概念强。

### 立刻验证（不用启动服务）

```powershell

uv run ruff check src
```

预期：

```text

```

`ruff format` 会自动整理缩进和空行；如果它改了你的文件，是正常的，看一眼 `git diff` 就行。`ruff check` 报 `I001` import 顺序问题时，用 `uv run ruff check --fix src` 自动修。

## A13. A 部分常见坑（按现象查）

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'steward'` | 不在 `E:\Steward`，或 A3 的 `uv add` 没跑完 | `Set-Location E:\Steward`；`uv sync` 补一次 |
| `ModuleNotFoundError: No module named 'app'` | 启动命令抄了手册的 `app.main:app` | 改成 `steward.main:app` |
| `ModuleNotFoundError: No module named 'sqlalchemy'` | A3 漏了最后一条 `uv add` | `uv add "sqlalchemy[asyncio]"` |
| `ValidationError: JWT_SECRET ... Field required` 或 `String should have at least 32 characters` | `.env` 没填、占位值没换、长度不足 32，**或 `.env` 带 BOM** | A7.4 生成密钥；按 2.5.3 查 BOM |
| `找不到与参数名称 i 匹配的参数` | 把 `curl` 写成了 `curl.exe` 之外 | 改 `curl.exe -i ...` |
| `UnicodeDecodeError` / `TOMLDecodeError` | 文件不是 UTF-8 无 BOM | 按 2.5.3 用 `WriteAllText` 重写 |
| `ruff check` 报 `I001` | import 顺序不对 | `uv run ruff check --fix src` |
| 配置改了不生效 | `APP_ROOT` 写成 `parents[2]`，或 `.env` 有 BOM | 改 `parents[3]`；用 A9 验证命令确认 `root=` 是 `E:\Steward` |
| 8001 被占 | 之前的服务没关 | `netstat -ano \| Select-String ":8001"`，或换 `--port 8002` |
| 日志每行打两遍 | `root.handlers.clear()` 被删了 | 对照 A10 补回来 |
| `uv add` 报网络超时 | 清华源没生效 | 回 A2.5 验证 `uv.lock` 里的 registry |
| `python -c "..."` 里的引号被吃掉 | 外层用了单引号，或命令里混进了 `$` | 按 2.5.5：外层双引号、内层单引号 |

**排查顺序**（手册附录 D）：读完整报错 → 确认刚才只动了哪个文件 → 打印中间值 → 最小复现 → 同一问题修 3 次还不行就停下来问我。不要连续瞎改。

## B2. 写 `docker-compose.yml`（项目根目录）

**用编辑器新建**，粘贴（YAML 对缩进敏感，别用 Tab）：

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: steward-pg
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${DB_USER:-steward}
      POSTGRES_DB: ${DB_NAME:-steward}
      POSTGRES_PASSWORD: ${DB_PASSWORD:?DB_PASSWORD must be set in .env}
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER:-steward} -d ${DB_NAME:-steward}"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  pgdata:
```

逐字段解释：

| 片段 | 作用 / 为什么 |
| --- | --- |
| `postgres:16-alpine` | 手册指定 PG 16；alpine 镜像体积小，本地开发够用 |
| `container_name: steward-pg` | 固定容器名，`docker compose exec` / `logs` 时好认 |
| `restart: unless-stopped` | 开机自起，但你手动 `docker compose stop` 后不会自己爬起来 |
| `${DB_USER:-steward}` | Compose **自动读取项目根 `.env`** 做变量替换；`:-` 表示没设就用默认值。密码只写在 `.env` 一处，不硬编码进 YAML（方案 11.2） |
| `${DB_PASSWORD:?...}` | `:?` 表示「没设置就直接报错」，不会用一个空密码悄悄起库；消息故意用英文，避免 YAML 插值时的编码问题 |
| `ports: "5432:5432"` | 左边宿主机端口，右边容器内端口。应用跑在宿主机，连 `127.0.0.1:5432` |
| `volumes: pgdata` | 命名卷，容器删了数据还在（手册 15.1「重启数据不丢」） |
| `healthcheck` | `docker compose ps` 能显示 `healthy`，比只看 `Up` 可靠 |
| **只有 postgres 一个服务** | Milvus / etcd / MinIO 是 P2 的事，手册明确「这周不要碰」。现在加只会吃内存、拖慢你 |

> ⚠️ 在 PowerShell 里**不要**用双引号 here-string 写这段 YAML：`${DB_USER:-steward}` 里的 `$` 会被 PowerShell 展开。用单引号 here-string `@'...'@`（见 2.5.3），或者直接用编辑器粘贴——这也是本教程推荐编辑器的原因之一。

> 手册 Day 0 讲的是 Windows 安装包 + 手动 `CREATE USER` / `CREATE DATABASE`。用 Docker 时，**`POSTGRES_USER` 和 `POSTGRES_DB` 会在首次启动时自动建好库和用户**，不需要再执行那两条 SQL。这是两条路线的差异，别照抄手册重复建。

## B6. B 部分常见坑

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| `failed to connect to the docker API` | Docker Desktop 没启动 | 回 B1，等图标稳定 |
| `DB_PASSWORD must be set in .env` | `.env` 没这个文件，或键名写错 | `Test-Path .env`；确认文件名不是 `.env.txt`，键名无空格 |
| 拉镜像很慢 / 超时 | 国内网络 | 等一等，或给 Docker Desktop 配镜像加速；不要改代码绕过去 |
| `port is already allocated` | 5432 被别的 PG 占用 | 把 ports 改成 `"5433:5432"`，同时把 `.env` 的 `DB_PORT` 改成 `5433`（容器内仍是 5432） |
| 密码里有 `@` `#` `/` 导致连接失败 | `.env` 里 `#` 会被当注释，URL 里 `@` 会截断 | **只用字母和数字**，这是最省事的做法 |
| `psql: command not found` | 在宿主机直接敲了 psql | 用 `docker compose exec postgres psql ...`，客户端在容器里 |
| 容器反复重启 | 卷里有旧数据、密码对不上 | `docker compose down -v` 后重新 `up -d`（**会删数据**，P0 阶段随便删） |
| compose 里 `${...}` 变成空 | 用双引号 here-string 写 YAML，被 PowerShell 展开了 `$` | 用编辑器粘贴，或单引号 here-string `@'...'@` |
| 想看数据到底存在哪 | — | `docker volume ls` 找 `steward_pgdata`；`docker volume inspect steward_pgdata` |
